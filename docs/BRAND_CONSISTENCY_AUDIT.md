## 1) الخطوط

### النظام الرسمي: **4 خطوط** (2 إنجليزي + 2 عربي)
معرّفة في `src/app/layout.tsx` عبر `next/font/google`:

| المتغير | الخط | اللغة | الاستخدام | الأوزان |
|---|---|---|---|---|
| `--font-en-display` | Space Grotesk | إنجليزي | عناوين / لوجو / labels | 400,500,600,700 |
| `--font-en-body` | Manrope | إنجليزي | نصوص / أزرار / تنقّل | 400,500,600,700,800 |
| `--font-ar-display` | IBM Plex Sans Arabic | عربي | عناوين عربية | 400,500,600,700 |
| `--font-ar-body` | Noto Sans Arabic | عربي | نصوص عربية | 400,500,600,700 |

النظام كان سليمًا أصلًا: لا `@font-face` يدوي، ولا خطوط خارجية، والتوجيه بين LTR/RTL مركزي في `globals.css`.

### التسريبات الثلاثة — **أُصلحت**

| # | المشكلة | الإصلاح | أثر بصري |
|---|---|---|---|
| 1 | `font-mono` مستخدم 7 مرات بينما `--font-mono` غير معرّف → يسقط على خط النظام الافتراضي، فيختلف الشكل من جهاز لآخر | عُرّف `--font-mono` صراحةً في `@theme` **بنفس مكدّس Tailwind الافتراضي بالحرف** | صفر — نفس البكسل، لكن المكدّس صار تحت سيطرتنا |
| 2 | `font-family: Georgia, serif` مكتوب حرفيًا (علامة الاقتباس في `.home-trust__quote`) | صار `var(--domi-font-quote)` مع سلسلة احتياطية أطول | صفر على Windows/macOS؛ **تحسّن** على Linux/Android حيث Georgia غير مثبّت |
| 3 | 6 عناصر `<text>` في `BeneathInterfaceSvg` بـ fallback `monospace` بينما القيمة الأساسية خط body | صار `var(--font-sans, system-ui, sans-serif)` | صفر — الـ fallback لا يُستخدم أصلًا لأن `--font-sans` معرّف دائمًا |

**قرار مؤجّل:** الـ 7 labels التي تستخدم `font-mono` تظهر الآن بخط النظام أحادي العرض. إن أردتها على خط البراند التقني، غيّر `--font-mono` إلى `var(--font-en-display)` — سطر واحد، لكنه **يغيّر الشكل**.

## 2) المسافات

### قبل: لا يوجد spacing scale إطلاقًا
`@theme` كان يعرّف tokens للخطوط والألوان والزوايا والحركة — لكن **صفر tokens للمسافات**.
النتيجة: 297 تصريح `padding/margin/gap`، منها **47 قيمة gap فريدة** و**85 padding** و**42 line-height** و**31 tracking**.

### بعد: سلّم معرّف + 156 تصريح محوّل

أُضيف إلى `globals.css` سلّم من ثلاث مجموعات، **كل قيمة فيه مأخوذة من قيمة يستخدمها الكود فعلًا** — فالتحويل دائمًا تبديل مطابق حرفيًا:

```
--domi-space-3xs … 4xl   0.25 / 0.5 / 0.75 / 1 / 1.5 / 2 / 3 / 4 / 6 / 8 rem
--domi-lh-none … arabic  1 / 1.15 / 1.3 / 1.5 / 1.65 / 1.75 / 1.85
--domi-track-tight … eyebrow  -0.06 / 0 / 0.14 / 0.2 / 0.22 em
```

> **لماذا `--domi-*` وليس `--spacing-*` / `--leading-*` / `--tracking-*`؟**
> هذه الأخيرة **مساحات أسماء محجوزة في Tailwind v4**. تعريف `--leading-snug: 1.4` مثلًا كان سيعيد ضبط كل `leading-snug` موجودة في الـ TSX من 1.375 إلى 1.4 — ثمانية عناصر تتحرك بصمت. البادئة `--domi-` تتبع العرف القائم في الملف (`--domi-radius-*`, `--domi-motion-*`) ولا تصطدم بشيء.

| المقياس | محوّل إلى توكنز | باقٍ حرفيًا |
|---|---|---|
| `gap` | 34 | 67 |
| `line-height` | 49 | 70 |
| `letter-spacing` | 14 | — |
| `padding` / `margin` (كل الصيغ) | 59 | — |
| **الإجمالي** | **156** | |

**لماذا لم تُحوَّل البقية؟** لأنها خارج السلّم، وتقريبها يحرّك عناصر 1–3 بكسل — وهذا يخالف شرط «بدون تخريب الشكل». القائمة كاملة في قسم «المؤجَّل» أدناه.

`letter-spacing: 0` (79 تصريحًا) تُرك عمدًا كما هو: تحويله إلى `var(--domi-track-none)` ضجيج بلا فائدة — الصفر صفر، ولن تغيّره مركزيًا أبدًا.

## 3) الألوان

### قبل: 217 لون hex + 184 قيمة rgba تلتف حول نظام توكنز سليم

### بعد

**أ) لوحة manal — وُثّقت كهوية عميل منفصلة ✅**
كانت أوضح خرق: 77 لونًا حرفيًا بلوحة كريمية/ذهبية مستقلة (`#174c44` وحده 28 مرة، أكثر من أي لون براند).
صارت **28 توكن مسمّى** في `@theme` تحت `--color-manal-*`، مع تعليق يشرح أنها هوية العميل لا خرقًا للهوية، وأنها **غير تفاعلية مع الثيم عمدًا** (الصفحة فاتحة بالتصميم ويجب ألا تنقلب مع مفتاح الثيم).

```
raw hex في مجلد manal:  77  →  0
```
الاستخدام صار `bg-manal-canvas` / `text-manal-gold-deep` بدل `bg-[#f3f0e9]` / `text-[#aa7440]`، ويمكن تغيير اللوحة كاملة من مكان واحد.

**ب) 4 تصريحات theme-scoped رُبطت بالتوكنز ✅**
`--cine-bg`, `--hero-surface`, `--hero-surface-elevated`, `--hero-primary-contrast` — كانت قيمًا حرفية داخل كتل `[data-theme="dark"]` / `[data-theme="light"]` تطابق توكن الثيم نفسه تمامًا، فصارت `var(--domi-*)`.

**ج) ما لم يُلمس عمدًا — وهذا مهم**
معظم الـ `#ffffff` في الكود **ليست** لون السطح، بل **شريك خلط** داخل `color-mix(in srgb, X 88%, #ffffff)` لصنع لمعة. ربطها بـ `var(--domi-surface-elevated)` كان سيجعلها `#101614` في الثيم الداكن — أي انقلاب كامل. تُركت كما هي.
كذلك `.domi-media-dialog` و`.home-water__heading h2`: نصوص فاتحة على خلفيات داكنة **دائمًا**، وربطها بـ `var(--domi-text)` كان سيجعلها داكنة على داكن في الثيم الفاتح.

**د) حارس ضد الانجراف المستقبلي ✅ — `npm run check:tokens`**
دمج الـ 60 أبيض والـ 55 أسود المتقاربة يتطلب مراجعة بصرية، فلم يُنفَّذ. لكن أُضيف **سقف مسجَّل لكل ملف** يمنع الكومة من النمو: أي ملف يُدخل ألوانًا حرفية جديدة يفشل الفحص.
السقف ينزل ولا يصعد — بعد أي تنظيف شغّل `node scripts/check-design-tokens.mjs --update` لتثبيت الرقم الأقل.

```
إجمالي الاستخدامات الحرفية:  413  →  357
```

## التحقق — كيف نعرف أن الشكل لم يتغيّر

ثلاث طبقات، كلها آلية:

1. **مقارنة على مستوى المصدر.** تُؤخذ نسخة `HEAD` من كل ملف CSS معدّل، ويُوسَّع كل توكن جديد إلى قيمته الحرفية، ثم تُقارن بايت ببايت:
   ```
   IDENTICAL after token expansion   ← جميع الملفات التسعة
   ```

2. **مقارنة على مستوى CSS المُصرَّف.** `globals.css` مرّ عبر PostCSS + Tailwind قبل وبعد، ثم قورنت مجموعة التصريحات بعد حلّ كل `var()`:
   ```
   distinct declarations  before=2173  after=2173
   الفروق: 4 فقط — وهي تحديدًا الأربعة المقصودة في (ب)، وكلها تُحلّ لنفس القيمة داخل نطاقها
   ```

3. **فحص توليد الأصناف.** كل صنف `manal-*` مستخدم في الـ TSX (38 صنفًا) له قاعدة مولَّدة فعليًا في CSS، وكل `var(--color-manal-*)` داخل الـ SVG معرّف. لا صنف صامت.

**فرق واحد مقصود ومفيد:** ألوان `@theme` المسجّلة تولّد نسخة احتياطية `color-mix(in srgb, …)` قبل نسخة `oklab` داخل `@supports`، بينما القيم الحرفية العشوائية لم تكن تفعل. النتيجة **متطابقة في كل متصفح حديث**، و**أفضل** في المتصفحات القديمة التي كانت تحصل على قيمة غير صالحة.

كما مرّ `tsc --noEmit` بنجاح، وكل ملفات CSS المعدّلة تُحلَّل بلا أخطاء.

## المؤجَّل — يحتاج موافقة بصرية

هذه لم تُنفَّذ لأنها **تحرّك بكسلات**. كل واحدة إصلاح ميكانيكي بسيط متى ما وافقت.

### أ) مسافات خارج السلّم (تقريبها يحرّك 1–3 بكسل)
```
9×0.7rem   9×0.6rem   8×0.65rem  8×0.35rem  6×0.55rem  5×7rem
3×3.2rem   3×2.5rem   3×0.9rem   3×0.8rem   3×0.4rem   3×0.45rem
2×8.5rem   2×7.5rem   2×2.1rem   2×0.85rem  2×0.28rem
1× لكل من: 2.8 / 2.2 / 1.8 / 1.6 / 1.3 / 1.25 / 1.2 / 1.1 / 0.32 / 0.3 rem
```
لاحظ العنقود `0.55 / 0.6 / 0.65 / 0.7` — أربع درجات لا تفرّق العين بينها، مرشّحة كلها لـ `--domi-space-xs` (0.75rem) أو `--domi-space-2xs` (0.5rem).

### ب) line-height خارج السلّم
```
5×0.98  5×1.25  5×1.35  5×1.4  4×0.9  4×1.8  3×0.92  3×1.28  3×1.55  3×1.7
2× لكل من: 0.88 / 0.94 / 0.95 / 1.18 / 1.2 / 1.32 / 1.45 / 1.6
1× لكل من: 0.7 / 0.77 / 0.78 / 0.8 / 0.84 / 0.86 / 1.08 / 1.12 / 1.34 / 1.38 / 1.42 / 1.72 / 1.82
```
النطاق `0.7 → 0.98` وحده فيه 12 درجة لعرض واحد (العناوين الضخمة).
وستة من هذه التصريحات تحمل `!important` داخل قواعد RTL في `globals.css` — إشارة إلى أن التوريث انكسر وعولج بالقوة لا بالبنية. تستحق إعادة نظر مستقلة.

### ج) دمج الأبيض والأسود المتقارب
60 درجة أبيض و55 درجة أسود بفروق 1–3 نقاط RGB. الفرق غير مرئي، لكن بعضها يقع داخل تدرّجات (`linear-gradient`) ضُبطت يدويًا لصنع لمعة خفيفة — فالدمج الأعمى قد يُسطّح تدرّجًا. يحتاج مراجعة حالة بحالة، لا سكربت.

### د) حارس tracking للعربية
الحماية الحالية (`letter-spacing: 0`) تغطي `h1–h6` و`p` تحت RTL فقط. أي `tracking-[.26em]` على `span` أو `div` عربي يتجاوزها.
**لم يُوسَّع الحارس عمدًا:** توسيعه إلى كل عنصر تحت `[dir="rtl"]` كان سيُسطّح الـ eyebrows اللاتينية داخل الأقسام العربية (مثل `PLATFORM MODULES` في صفحة manal) — وهي متباعدة الحروف بقصد. الحل الصحيح يحتاج تمييز النص العربي عن اللاتيني، وهو قرار تصميمي لا سكربت.
